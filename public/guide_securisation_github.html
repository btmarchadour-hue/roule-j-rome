Guide de Régularisation & Sécurisation GitHub

Projet : Char à Voile du Bout du Monde — Application « Ça roule ? » (Lestrevet / Pentrez)
Auteur : Sheldon (DevOps) · Document de procédure d'étanchéité Dev / Production
Constat initial : Lors d'une synchronisation automatique depuis Google AI Studio, le code a été poussé directement sur la branche de production principal au lieu de la branche de développement dev.

1. La Cause Technique

Sur GitHub.com, chaque dépôt a une « Default branch » (branche par défaut). Si cette branche par défaut est définie sur principal, toute interface externe (comme AI Studio) synchronise par défaut sur celle-ci.
Pour rétablir une étanchéité absolue, nous devons inverser cette configuration : faire de dev la branche de travail par défaut et cadenasser principal avec une règle d'écluse.

2. Procédure de Régularisation en 4 Étapes

Étape 1 : Passer la branche « dev » en branche par défaut
  1. Connectez-vous sur votre compte sur github.com.
  2. Ouvrez votre dépôt de char à voile (ex: char-a-voile-lestrevet).
  3. Cliquez sur l'onglet Settings (la roue crantée tout à droite dans les menus du haut).
  4. Dans la colonne de gauche, cliquez sur Branches.
  5. Sous la section Default branch, cliquez sur l'icône de double-flèche (Switch to another branch).
  6. Sélectionnez dev dans la liste déroulante, puis cliquez sur Update et confirmez (I understand, update the default branch).
✓ Résultat : À partir de maintenant, toute synchronisation venant d'AI Studio atterrira à 100 % sur dev.
Étape 2 : Cadenasser la branche « principal » (Règle d'Écluse)
  1. Toujours sur GitHub dans Settings > Branches.
  2. Dans la section Branch protection rules, cliquez sur Add branch protection rule (ou Add rule).
  3. Dans le champ Branch name pattern, écrivez exactement : principal
  4. Cochez les deux protections indispensables :
    • [x] Require a pull request before merging (interdit tout push direct, force la validation par revue).
    • [x] Do not allow bypassing the above settings (même vous en tant qu'administrateur ne pouvez pas écraser la prod par erreur).
  5. Descendez tout en bas de la page et cliquez sur Create (ou Save changes).
✓ Résultat : La branche de production principal est blindée. Tout envoi direct sera automatiquement rejeté par GitHub.
Étape 3 : Aligner les deux branches

Si du code a été envoyé sur principal ou si dev a de l'avance, nous alignons les deux branches au même niveau :

  1. Allez dans l'onglet Pull requests de votre dépôt.
  2. Cliquez sur le bouton vert New pull request.
  3. Configurez les deux branches :
    • base : principal
    • compare : dev
  4. Cliquez sur Create pull request, donnez le titre « Alignement et validation des modules 1 à 7 », puis cliquez sur le bouton vert Merge pull request.
Étape 4 : La règle d'or pour vos prochains développements
  • Pendant le travail : Vous travaillez et synchronisez avec AI Studio ➔ tout arrive en toute sécurité sur dev.
  • Pour tester : Vous testez sur l'adresse URL de Dev / Preview avec la base de test.
  • Pour livrer à Jérôme en Production : Quand tout est 100 % validé, vous ouvrez GitHub et vous fusionnez dev vers principal via la Pull Request.

3. Synthèse de l'Architecture Sécurisée

Branche Rôle Accès Base de données
dev (Par défaut) Atelier de travail / tests Push direct depuis AI Studio autorisé Base de test isolée
principal (Protégée) Version officielle club Écluse verrouillée (Pull Request obligatoire) Base officielle de l'école
